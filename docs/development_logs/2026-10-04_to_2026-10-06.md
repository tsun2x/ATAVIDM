## 2026-10-04 16:00 — Enable supervised local OCR and report plates

### Objective

Enable the thesis demo to run local OCR through an explicit regular-app opt-in, correct the case evidence linkage, and include plate information in reports without treating machine output as verified identity.

### Summary

Added an explicit `TAVIDM_PLATE_OCR_APP=1` mode with private evidence-root and database-path validation; OCR remains off unless the process explicitly opts in. Removed the passing-evaluation requirement for supervised local inference while retaining artifact hash validation. Fixed case-linked OCR evidence lookup, clarified the Review Queue path to case-level administrator verification, and added plate and legal-mapping labels to violation details and PDF/Excel reports. OCR candidates remain labeled unverified; no database schema or automatic decision behavior changed.

### Detailed Changes

Regular-app OCR requires the explicit app flag, an enabled JSON config, validated model/config hashes, and evidence storage under the configured private evidence root, separate from the database. The ordinary app remains disabled when the flag is absent. Evidence in PDF and Excel reports distinguishes a human-verified plate from an OCR candidate; if association is uncertain, the report says so. Legal mapping status is labeled separately from case outcome and plate verification.

### Known Limitations

OCR operates only on newly processed frames; existing observations require reprocessing if an attempt is needed. A generated report is a snapshot and must be regenerated to include later plate verification.

### Risks

OCR remains experimental and local. Machine text is unverified until an administrator confirms it; it does not establish offender identity or a violation decision.
