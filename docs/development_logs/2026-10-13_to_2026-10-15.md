## 2026-10-13 10:49 — Resume pending video annotations

### Objective

Allow users to return to an uploaded video that still needs annotation and recover annotation work after closing the editor.

### Summary

Pending uploads now appear in the uploaded-video list before the annotation wizard opens. Added a visible annotation action for the selected video, with saved annotations loaded from the server and unsaved scene edits restored from browser storage. The upload list updates an existing row after save instead of creating a duplicate.

### Files Modified

#### Modified

- `templates/live_monitor.html` — Added the selected-video annotation action.
- `static/js/live_monitor.js` — Opens the editor for saved annotations and pending videos, loading their templates and annotation data.
- `static/js/upload.js` — Stores scene edits in local browser storage, restores drafts, exposes pending uploads in the list, and updates rows after saves.
- `docs/development_logs/2026-10-13_to_2026-10-15.md` — Recorded this implementation.

### Detailed Changes

Editor changes are saved as a per-video browser draft while the user draws. Closing the modal preserves that draft, and reopening the selected video restores it in the editor. A successful server save removes the draft. Videos requiring annotation are added to the list immediately after upload, and later save responses update the same row.

### Database Changes

None.

### API Changes

None. The UI uses the existing annotation and zone-template endpoints.

### UI / UX Changes

The selected-video footer now offers “View / Edit Annotation” for videos with saved annotations and “Start / Resume Annotation” for videos without one. The action is hidden during processing.

### Dependencies

None.

### Testing

JavaScript syntax checks passed for `static/js/live_monitor.js` and `static/js/upload.js`; `git diff --check` passed. The application and test suite were not run.

### Performance Notes

Draft serialization is local to the browser and uses the existing scene document format.

### Known Limitations

Unsaved drafts are stored in this browser only. They are not synchronized to the server or other devices until the user saves the annotation.

### Risks

Browser storage can be unavailable or full; in that case editing remains usable, but draft recovery is not available.

### Next Recommended Steps

Verify closing and reopening an annotating video in the running application, then save and confirm the video becomes ready for processing.
