## 2026-07-07 22:45 — MP4 Video Upload Workflow

### Objective

- Verify whether TAVIDM supports uploading pre-recorded traffic videos.
- Implement a complete upload workflow if missing, integrated with the existing UI and architecture.
- Save uploaded MP4 files to `dataset/raw/` and register them in SQLite for future pipeline processing (no YOLOv8 processing yet).

---

### Summary

Analysis confirmed no upload system existed—only mock video metadata and a placeholder storage directory. Implemented a full MP4 upload workflow on the Live Monitor page with drag-and-drop, file picker, client/server validation, progress bar, cancel support, and JSON API responses. Uploaded videos are saved securely, registered via `database/db.py`, and appear in the video list for future processing.

---

### Files Modified

#### Created

- `core/upload.py`
  - Upload validation, secure filename handling, and file save logic.
- `static/js/upload.js`
  - Frontend upload handler with drag-and-drop, XHR progress, and cancel.

#### Modified

- `app.py`
  - Added `POST /api/upload-video`, `GET /api/videos`, DB integration, and dynamic video list from SQLite.
- `config.py`
  - Upload folder, max size, and allowed extension configuration.
- `templates/live_monitor.html`
  - Upload card with dropzone, condition selector, progress UI.
- `static/css/style.css`
  - Upload dropzone and selected-file panel styles.
- `.env.example`
  - `UPLOAD_FOLDER` and `MAX_UPLOAD_MB` variables.

#### Renamed

None.

#### Deleted

None.

---

### Detailed Changes

- **Analysis:** No upload page, endpoint, file input, drag-and-drop, or backend save logic existed. Live Monitor “Uploaded Videos” list used hardcoded mock data only. `dataset/raw/` and `db.insert_video()` were present but unwired.
- **Backend:** `core/upload.py` validates MP4 type and size, uses `werkzeug.secure_filename`, avoids collisions, saves to `dataset/raw/`, registers row in `videos` table with `processed=0`.
- **API:** `POST /api/upload-video` returns JSON success/error; `GET /api/videos` lists merged DB + seed videos; 413 handler for oversized uploads.
- **Frontend:** Upload panel on Live Monitor sidebar; drag-and-drop zone; browse button; selected filename display; traffic condition selector; progress bar; loading/cancel states; success/error toasts; new video prepended to list with “NEW” badge.
- **Integration:** `get_videos_for_ui()` merges DB uploads with seed demo videos; dashboard stats use live video counts.

---

### Technical Explanation

Upload logic is isolated in `core/upload.py` to keep `app.py` thin. Configuration lives in `config.py` with env overrides. The frontend uses `XMLHttpRequest` + `FormData` for upload progress and abort support (fetch does not expose upload progress). SQLite registration uses existing `database/db.py` helpers—no schema changes required. YOLOv8 pipeline is intentionally not invoked; videos are queued with `processed=0`.

---

### Code Impact

- Live Monitor is now the primary video ingestion UI.
- Video list is partially dynamic (DB-backed uploads + seed fallbacks).
- App startup calls `db.init_db()` and ensures upload directory exists.

---

### Database Changes

None (uses existing `videos` table via `insert_video()`).

---

### API Changes

- `POST /api/upload-video` — multipart upload, returns `{ success, video, message }` or `{ success: false, error }`.
- `GET /api/videos` — returns `{ success, videos }`.

---

### UI / UX Changes

- Upload card on Live Monitor with drag-and-drop MP4 zone.
- Progress indicator, cancel button, condition selector, success/error notifications.
- Newly uploaded videos appear at top of list with “NEW” badge and “Pending processing” status.

---

### Dependencies

None (uses existing Flask/Werkzeug stack).
