## 2026-09-17 20:00 — Add passage counting and safe processing cancellation

### Objective

Separate frame-level detection observations from physical vehicle passages and allow an authorized operator to stop one queued or running processing attempt safely.

## 2026-09-17 20:55 — Retire stale annotation results and add confirmed-dependent delete consent

### Objective

Prevent an edited scene annotation from continuing to display an older completed run, and allow administrators to intentionally delete a video together with dependent confirmed violations only after an additional explicit acknowledgment.

### Summary

Completed runs with `results_removed_at` are no longer selected as current UI results. Changing an existing annotation retires detections, pending or dismissed machine-review rows, and annotated run artifacts, while preserving confirmed violations as historical reviewed records and returning the video to `ready`. The permanent-delete modal now has a separate unchecked confirmation for deleting dependent confirmed violations; report references continue to block deletion.

Follow-up UI verification found that the processing preview rendered only the legacy zone projection and that uploaded-video row state was not synchronized after processing or deletion. The preview now renders the complete saved scene document (zones, lanes, flow arrows, thresholds, markings, signs, and activity regions). Processing runs persist the annotation ID and full scene snapshot in their geometry history. Video rows now visibly transition through Processing and Processed, update bulk eligibility, and clear stale selection state after deletion.

### Files Modified

- `app.py`
- `core/video_lifecycle.py`
- `core/frame_annotate.py`
- `core/video_processor.py`
- `database/sqlite_adapter.py`
- `static/js/live_monitor.js`
- `templates/live_monitor.html`
- `tests/test_upload_processing_ux.py`

### Safety and Audit Behavior

- Annotation edits are rejected while the video is queued or processing.
- Confirmed violations are never silently invalidated by an annotation edit.
- Filename confirmation remains mandatory for permanent deletion.
- Deleting confirmed dependents requires a separate boolean acknowledgment and records the deleted count and override in the durable system audit event.
- Existing report references remain a hard deletion block.
