## 2026-09-10 22:15 — Raise configurable upload limit to 3 GiB

### Objective

---

### Summary

Changed the environment-backed `MAX_UPLOAD_MB` default to 3072 MiB. The existing Flask request limit, server validation, browser limit display, and client-side validation continue to derive from the same setting. Documentation and a regression test now reflect the 3 GiB default.

---

### Files Modified

- `config.py`
  - Changed the default `MAX_UPLOAD_MB` value from 500 to 3072.
- `.env.example`
  - Updated the example value and storage warning for the 3 GiB default.
- `README.md`
  - Updated configuration, large-upload, and troubleshooting documentation.
- `tests/test_upload.py`
  - Added a regression test for the 3072 MiB and byte-level content-length defaults.
- `docs/development_logs/2026-09-10_to_2026-09-12.md`
  - Added this development entry.

---

### Detailed Changes

- `MAX_CONTENT_LENGTH` now resolves to `3072 * 1024 * 1024` bytes under default configuration.
- `MAX_UPLOAD_MB` remains overrideable through the environment.
- The existing 500 MiB `UPLOAD_DISK_HEADROOM_MB` default remains unchanged.
- No upload buffering, persistence, processing-queue, database, or API contract was changed.

---

### Technical Explanation

Flask, the upload validator, the 413 response, template context, and browser validation already consume the shared configuration value. Raising the single default therefore updates the complete upload boundary without duplicating constants. Uploaded files continue to be saved through Werkzeug's file stream rather than being deliberately loaded into application memory as one 3 GiB value.

---

### Code Impact

Default installations accept individual MP4 requests up to 3 GiB. Deployments can still set a lower or higher `MAX_UPLOAD_MB` explicitly.

### Database Changes

None.

### API Changes
