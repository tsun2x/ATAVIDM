## 2026-11-19 20:12 — Add pickup-crop person submodel

### Objective

Add a third inference stage that uses each detected pickup truck crop to find and outline visible people during uploaded-video and live-camera processing.

### Summary

Added a separate YOLOv8m person detector that scans expanded crops around primary-detector pickup tracks, maps person boxes back to the source frame, and assigns lightweight per-pickup identities for review. Its boxes appear in annotated output and can feed the existing pickup review collector. Supplemental detections remain outside the primary detection records and violation rules.

### Files Modified

#### Created

- `core/pickup_person_scan.py` — lazy-loaded pickup-crop inference, person-class filtering, source-frame box mapping, and per-pickup association IDs.
- `tests/test_pickup_person_scan.py` — checks crop inference, coordinate mapping, stable identity, class filtering, and no-work paths.
- `docs/development_logs/2026-11-19_to_2026-11-21.md` — this development record.

#### Modified

- `.env.example` — documents the pickup-person submodel toggle and optional custom weights path.
- `config.py` — adds `TAVIDM_PICKUP_PERSON_ENABLED` and `TAVIDM_PICKUP_PERSON_WEIGHTS` configuration.
- `core/video_processor.py` — invokes the crop detector for uploaded videos and renders supplemental boxes while keeping rules and detection counts on the primary tracks.
- `core/live_stream.py` — runs the same crop pass under the live-frame GPU reservation and publishes the outlined boxes.
- `core/pickup_detail_review.py` — associates crop-model people with their source pickup and records their evidence source.
- `tests/test_pickup_detail_review.py` — covers riders whose detected person box extends above the primary pickup box.

### Detailed Changes

- The submodel batches detected pickup crops per frame and requests only its `person` class. Crops include extra space above the pickup box for riders whose bodies extend above the vehicle outline.
- Predictions are translated from crop coordinates back to the frame. Overlapping primary-person boxes are deduplicated, and the submodel maintains lightweight person IDs across adjacent frames.
- Inference failure disables only this optional stage for the current scanner instance. The main detector, tracking, rule evaluation, and persisted detection totals continue unaffected.
- Blank custom weights use the project's pretrained YOLOv8m weights; a pickup-specific person checkpoint can be selected with the environment setting.

### Technical Explanation

The crop detector is instantiated per uploaded video or live camera. In live mode, inference runs inside the existing non-waiting GPU slot reservation. Synthetic person detections are passed only to the pickup-review collector and annotation renderer; they are not passed to the rule engine or inserted into the canonical detection table.

### Code Impact

The uploaded-video and live annotation paths now include person outlines returned by the pickup crop submodel. Existing pickup review logic can create review-only leads from these detections, including people above the pickup detector's original box. No violation rules consume the new detections.

### Performance Notes

The additional YOLO inference runs only when a pickup is detected and batches crops from the frame. It adds compute and model memory use; the setting can disable it, and the model can be replaced via configuration.

### Known Limitations

The default model is general COCO person detection, not a pickup-bed-specific trained checkpoint. It scans the expanded pickup crop rather than a learned cargo-bed mask; a visible person elsewhere inside that crop can therefore become a review lead. Human review remains required.

### Risks

None beyond the documented compute cost and crop-context limitation.
