## 2026-10-19 13:49 — Fix Three Regressions in Reports and Evaluation

### Objective

Fix three reproduced regressions in the recently added model comparison, Reports preview request lifecycle, and bounded report export implementation.

### Summary

Corrected Ultralytics per-class metric extraction for scalar AP arrays and sparse class IDs. Reports preview responses and uploader video-option requests now ignore stale completions. Report exports now materialize the filtered count, selected cases, case policy records, and outcome action records from one SQLite read snapshot before rendering or writing history.

### Detailed Changes

The motorcycle extractor now reads AP50 and AP50–95 from their installed Ultralytics per-class properties and maps precision, recall, and AP values using the same represented-class position. Unsupported or empty metric results report unavailable metrics and cannot be recorded as a successful model validation.

Each preview request increments an identity and aborts its predecessor before checking whether a video is selected. Response and error handlers check that identity before updating the page. Uploader option requests use the same identity guard, preventing an older account response from replacing the active account’s list.

The new export adapter method begins a read transaction only when no shared transaction is already active, then counts, selects, and batch-loads policy/action metadata within that snapshot. Rows are fully materialized before the adapter returns, so report rendering and report-history writes happen after the read transaction closes. More than 5,000 matches returns the total without rows; report generation raises before creating the file or history row. Existing ownership and filter construction remain in use.

## 2026-10-21 11:29 — Prevent Reports Preview Cross-Account Races

### Objective

Changing the Reports source account must immediately invalidate any pending preview and video selection from the prior account. A failed or delayed video list request must not allow stale results to appear or be exported.

---

### Summary

The uploader change now clears and disables the video selector, clears preview rows/count/pagination, aborts and invalidates the active preview, and disables report generation before requesting the new account's video list. Generation and preview requests stay blocked while the list is loading or unavailable. Deterministic deferred-request tests cover late success/error responses, rapid account switches, all-account selection, empty lists, and recovery with a valid selection.

---

### Files Modified

#### Modified

- `static/js/reports.js`
  - Invalidate old preview state synchronously on source change; guard loading, failure, and generation states.
- `tests/js/test_reports_request_races.cjs`
  - Add deferred-promise regression cases for account changes and video-list states.
- `docs/development_logs/2026-10-19_to_2026-10-21.md`
  - Record this completed fix and its focused verification.

---

### Detailed Changes

- Added a shared preview invalidation path that aborts the current controller, advances the preview request identity, resets pagination, and clears visible case data and count.
- Account refresh now clears the selected video before the fetch, disables the selector and both generation buttons, and only restores them after the active account's list succeeds.
- Failed list loads leave the selector and generation disabled. A successful empty list shows a clear “No videos” state; a later successful list can be selected and previewed normally.
- Added identity checks for source-list and preview responses so late work cannot replace the active account's UI.

---

### Technical Explanation

The bug came from guarding the video-list response identity while leaving the separate preview request identity active until the list succeeded. The source change now advances the preview identity and aborts its controller synchronously, before starting the list request. `loadPreview` and `generateReport` also check list readiness, so even a programmatic event cannot use a stale video/account pair while options are loading or unavailable.

---

### Code Impact

Reports page client-side state handling only. The server endpoints, request/response formats, and database remain unchanged.
