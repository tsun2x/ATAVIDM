### Objective

### Detailed Changes

- **Detection pipeline**: `Detector.track_frame()` runs Ultralytics YOLOv8s with ByteTrack (`bytetrack.yaml`), filtering to the configured class list and confidence threshold. Custom weights (e.g. `models/tavidm_yolov8s.pt`) are preferred; otherwise the pretrained COCO checkpoint downloads automatically. Helmet/rider rules stay inactive on COCO weights.
- **Rule engine**: zone rules use point-in-polygon on bounding-box reference points with per-rule dwell thresholds; Counterflow compares track direction to the annotated active-lane flow with a minimum displacement; Truck Ban checks class + zone + configured hours; Motorcycle Overloading counts riders per motorcycle track.
- **Violation workflow**: every fired rule saves an annotated evidence snapshot and inserts a review-queue row banded by confidence (auto-review bands from settings). Operators confirm or dismiss items; confirmations create violation records used by dashboards, analytics, and reports.
- **Authentication and roles**: bcrypt-hashed passwords, Flask sessions, and decorators enforce page/API access — viewer (read-only dashboards), enforcer (review + reports), admin (settings, users, cameras). Default `admin`/`admin123` account is bootstrapped and legacy placeholder hashes are repaired.
- **Analytics and reports**: SQL aggregations power dashboard stats, hourly/daily/monthly charts, and vehicle-class breakdowns. Reports are generated as real PDF (fpdf2, latin-1-safe cell sanitization) and Excel (openpyxl) files stored under `static/reports/` and recorded in the `reports` table.
- **Live monitoring**: cameras are stored in the database; `StreamManager` starts a worker per camera which reconnects on failure and serves annotated MJPEG frames at `/api/cameras/<id>/stream`.

---

### Technical Explanation

- Kept the existing Flask monolith: `core/` modules for processing, `database/` facade for persistence, Jinja2 + vanilla JS for UI. Synchronization changed module internals and added modules without altering the overall architecture.
- Ultralytics `model.track(persist=True)` provides both detection and ByteTrack association in one call, avoiding a hand-rolled tracker; `core/tracker.py` layers motion history (trajectory, direction, dwell) on top of the returned track IDs.
- Rule parameters (confidence threshold, dwell thresholds, truck-ban hours, review bands) live in the `system_settings` table so admins tune behavior at runtime without code changes.
- Schema migrations run idempotently at startup; the users-table rebuild commits pending work and temporarily disables `PRAGMA foreign_keys` to satisfy SQLite's table-recreation constraints.
- PDF cells are sanitized to latin-1 because fpdf2 core fonts cannot encode characters like the em dash.
