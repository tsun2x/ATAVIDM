### Detailed Changes

Documentation update only.

The specification records:

- Hierarchical classification: Broad Vehicle Class → Specific Vehicle Type → optional attributes.
- Required operational classes: Motorcycle; Car / Passenger Vehicle; SUV / Crossover; Van; Truck; Bus.
- PUV operational types that must remain distinct: Jeepney, UV Express / Van, Tricycle, Piaggio (Piaggio retained as an operational label).
- Classification determines rule applicability only; it does not constitute a violation.
- Classification confidence is separate from violation confidence.
- UNKNOWN / UNCERTAIN must be representable.
- Classification should persist on the tracked vehicle; vehicle class is not a unique identity.
- ByteTrack remains responsible for tracking; the Violation Engine consumes classification.
- Operational classification and legal classification stay conceptually separate.
- Later explicit project decisions supersede this document.

---

### Technical Explanation

The specification was stored as project documentation so Cursor, Hermes, and future sessions load the same frozen decisions. Implementation was intentionally not started because several classification details remain design-in-progress, and the spec forbids inventing unspecified mapping rules.

### Known Limitations

Current code conflicts with this specification (spec left unchanged; implementation not rewritten in this task):

- `core/detection_config.py` uses a flat `DETECTION_CLASSES` list and maps vehicles to four manuscript categories (`Private Vehicle`, `Public Utility Vehicle`, `Commercial Vehicle`, `Two-Wheeled Vehicle`) via `VEHICLE_CATEGORIES` / `vehicle_category()`.
- Missing operational types in the detector registry: Van, UV Express / Van, Tricycle, Piaggio; no UNKNOWN / UNCERTAIN vehicle type.
- Bus is grouped under `Public Utility Vehicle` in `VEHICLE_CATEGORIES`; the spec treats Bus as a dedicated class distinct from the PUV operational types Jeepney / UV Express / Van / Tricycle / Piaggio.
- Bicycle is grouped with motorcycle as `Two-Wheeled Vehicle`; the spec treats motorcycle as its own broad class and forbids collapsing Tricycle/Piaggio into Motorcycle.
- `core/tracker.py` `TrackHistory` stores a single `class_label` from the first observation; it does not accumulate track-level classification confidence or hierarchical fields (`broad_class`, `vehicle_type`, `is_puv`, `is_motorcycle`, `is_truck`).
- `core/violation_engine.py` consumes YOLO `class_label` / `vehicle_category()` for applicability (for example motorcycle and truck string equality). Classification and violation confidence remain a single detection `confidence` on events.
- Jeepney exists as a YOLO class but is not exposed as `broad_class = PUV` + `vehicle_type = Jeepney` with boolean flags.
- A separate Violation Engine specification document is required by this spec and is not yet in the repository.

---

### Risks

If future implementation maps the new hierarchy onto the existing four-category `vehicle_class` database column without preserving specific types, operational distinctions (Jeepney, Piaggio, Tricycle, UV Express / Van) can be lost. Schema changes were not made in this task.

### Known Limitations

Current code conflicts with this specification (spec left unchanged; implementation not rewritten):

- `core/detection_config.py` still defines an 11-type canonical set that fuses Illegal Parking / Illegal Terminal and uses older names (`Substandard Helmet`, `Unauthorized Passengers in Pickup/Truck Cargo Area`).
- Implemented rules are zone/dwell based: fused parking/terminal (10s stop / 30s park), obstruction 10s in active lane (crossing block 3s mapped to Obstruction), counterflow uses global `VIOLATION_PERSISTENCE_SEC` (1.5s) rather than 4s/2s, truck-ban flags trucks in-zone during the window without pre-ban parked-state exemption.
- PUV loading rule treats jeepney+bus as PUV; spec Illegal Terminal requires Jeepney / UV Express / Van / Tricycle / Piaggio plus passenger/terminal behavior, not time-in-zone alone.
- Restricted-lane presence is mapped to pavement-markings; spec forbids automatic marking-crossing violations and leaves marking taxonomy TBD.
- Single global detection-confidence bands (`CONF_AUTO_QUEUE` / `CONF_CAREFUL_REVIEW`); no per-violation detection vs violation confidence pair; `ViolationEvent.confidence` copies detector confidence.
- Evidence is a single annotated snapshot (`core/evidence.py`), not a 6s+duration+3s window; no post-candidate ALPR stage.
- Track history is motion-only; no vehicle-state vocabulary (MOVING / PARKED / UNKNOWN) or three-valued context.
- Motorcycle Overloading currently uses a >2 rider heuristic; spec says occupancy limits are not frozen.
- Low-confidence detections are still queued rather than ignored; spec allows ignore for insufficient evidence.

### Risks

If implementation proceeds from existing code names, Illegal Parking and Illegal Terminal can remain fused. Heuristic dwell values in code (30s parking, 10s obstruction, 1.5s persistence) must not be treated as frozen spec values.
