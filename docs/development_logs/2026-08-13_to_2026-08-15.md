### Summary

### Detailed Changes

**Test Suite Structure:**
- `conftest.py`: Provides test_db fixture that creates isolated SQLite databases with full schema. auth_db fixture creates test users (admin, enforcer, viewer). Includes synthetic violation tracks for testing all 10 rules.
- `test_violation_engine.py`: Tests each violation type with proper frame numbers, dwell times, and zone geometries. Uses synthetic TrackState objects to simulate detector output.
- `test_review_queue.py`: Tests confirm/dismiss workflow, status transitions, timestamp preservation, and the double-confirm idempotency fix.
- `test_auth.py`: Tests password hashing, authentication flow, role decorators, and user CRUD operations.

**Bug Fix:**
The `confirm_review_item()` function now validates that the review item's status is 'pending' before creating a violation. Previously, confirming an already-confirmed item would silently insert a duplicate violation. The fix raises `ValueError` with a clear message: `"Review item {id} is not pending (status: confirmed)"`.

---

### Code Impact

```python
# Before (bug):
def confirm_review_item(review_id: int, reviewed_by: int) -> int:
    # ... fetch row ...
    if row is None:
        raise ValueError(f"Review item {review_id} not found")
    # BUG: No check for pending status - allows duplicates

# After (fixed):
def confirm_review_item(review_id: int, reviewed_by: int) -> int:
    # ... fetch row ...
    if row is None:
        raise ValueError(f"Review item {review_id} not found")
    row_status = row["status"] if "status" in row.keys() else None
    if row_status != "pending":
        raise ValueError(f"Review item {review_id} is not pending (status: {row_status})")
```
