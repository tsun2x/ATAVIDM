## 2026-09-19 03:06 — Persistent Processing Jobs and Results History

### Objective

Keep active video-processing jobs visible across page and video navigation, and add a cross-video history surface with truthful result preview controls.

---

### Summary

Implemented a SQLite-backed global processing-jobs API, a single authenticated browser polling controller and drawer, and Active/Completed job views in Live Monitor. The UI now reconstructs state from `processing_runs`, retains the last snapshot during transient failures, deep-links to a selected video/run, and exposes annotated preview/download only for a current completed result with an existing guarded artifact. Legacy processing-run schemas are also handled safely when `results_removed_at` is absent.

---

### Files Modified

#### Created

- `core/processing_jobs.py` — Builds presentation-safe global job snapshots and validates result artifacts.
- `static/js/processing_jobs.js` — Owns the single page-level polling loop, global drawer rendering, and update event.
- `tests/test_processing_jobs.py` — Covers grouping, authority, filtering, authentication, URLs, roles, templates, and SQLite reconstruction.
- `tests/js/test_processing_jobs_controller.cjs` — Covers idempotent polling, retry retention, deep-link parsing, and terminal-state labels.
- `docs/specs/2026-09-19-global-processing-jobs-design.md` — Records the approved hybrid UX and authority model.
- `docs/plans/2026-09-19-global-processing-jobs.md` — Records the implementation and verification plan.
- `docs/development_logs/2026-09-19_to_2026-09-21.md` — Starts the active segmented development log.

#### Modified

- `app.py` — Adds authenticated `GET /api/processing-jobs` with bounded validation and role-derived stop capability.
- `database/sqlite_adapter.py` — Adds the bounded cross-video query, result/latest flags, normalized summaries, queue ordering, and legacy-column guards.
- `database/adapter_base.py` — Adds the processing-jobs adapter contract.
- `database/db.py` — Exposes the adapter method through the stable database facade.

- `templates/live_monitor.html` — Adds Active and Completed processing-job sections.
- `static/js/live_monitor.js` — Projects global snapshots into Live Monitor, restores deep-linked selection, and reuses the existing run-scoped stop endpoint.
- `static/css/style.css` — Styles the global drawer and responsive Live Monitor job cards.

---

### Detailed Changes

- Uses `processing_runs` joined to `videos` as the sole durable UI authority.
- Groups queued/running attempts separately from bounded completed/failed/cancelled history.
- Preserves zero-detection completed runs as authoritative and labels older completions superseded.
- Suppresses filesystem paths and invalid, removed, missing, or non-current annotated-result actions.
- Polls every 1.5 seconds while active and every 10 seconds while idle, with a bounded 5–30 second reconnect backoff.
- Keeps exactly one global timer per browser page and publishes `tavidm:processing-jobs-updated` for Live Monitor.
- Keeps per-video high-frequency status polling only for the selected active run.
- Provides role-safe Stop controls and read-only history for viewers.

---

### Technical Explanation

The server performs one bounded SQLite query for active rows plus recent terminal IDs and computes current-result authority from explicit run ownership flags rather than detection counts. A presentation service checks artifact containment and existence before returning guarded media URLs. The global JavaScript controller owns the polling lifecycle; Live Monitor subscribes to its document event instead of creating another global poller.

---

### Code Impact

Existing process, per-video status, cancellation, history, media, removal, and deletion endpoints remain authoritative. No queue, worker, detector, tracker, rule-engine, or schema replacement was introduced.

---

### Database Changes

None. The feature reads the existing `processing_runs` and `videos` tables.

---

### API Changes

- Added authenticated `GET /api/processing-jobs`.
- Supports bounded `recent_limit` and optional `video_id` query parameters.
- Returns `active`, `recent`, `server_time`, `poll_after_ms`, authority flags, safe navigation/media URLs, and role-derived `can_stop`.

---

### UI / UX Changes

- Added an authenticated top-bar active-job count and processing drawer on all application pages.
- Added Active and Completed job tabs to Live Monitor.
- Added deep links that restore the requested video, run, and tab.
- Shows progress/FPS/queue data for active jobs and result/candidate/crossing summaries for terminal jobs.

## 2026-09-19 20:50 — Six-Second Violation Evidence Playback

### Objective

Expose playable temporal evidence for detected violations using three seconds of context before and after the event instead of relying on still images alone.

---

### Summary

Changed the existing temporal evidence pre-roll from six seconds to three seconds while retaining the three-second post-roll. Added the finalized clip URL to review and violation presentation data and added a playable Clip tab to both evidence dialogs; still scene and vehicle-crop evidence remain available.

---

### Files Modified

- `app.py` — Exposes finalized clip URLs to review and violation UI models.
- `core/temporal_evidence.py` — Uses a three-second pre-roll and three-second post-roll.
- `static/js/review_queue.js` — Adds evidence video playback to review items.
- `static/js/violations.js` — Adds evidence video playback to confirmed violations.
- `tests/test_ui_accessibility.py` — Covers the clip URL/UI contract and window constants.
- `tests/test_integration_remediation.py` — Updates the persisted temporal-window expectation.
- `docs/development_logs/2026-09-19_to_2026-09-21.md` — Records this feature.

---

### Detailed Changes

- Existing temporal evidence generation and database fields were reused.
- Evidence clips cover three seconds before confirmation, the violation episode, and three seconds after its end.
- Review Queue and Violations modals now include Scene, Vehicle, and Clip tabs.
- Missing or unfinished clips display an explicit unavailable state.

---

### Technical Explanation

The processing pipeline already finalized MP4 clips and propagated their paths through review confirmation. This change exposes those paths through the existing UI serializers and renders native HTML video controls without adding a schema or dependency.

---

### Code Impact

Still-image evidence and manual-review behavior remain intact. Previously generated evidence retains its stored duration metadata; the new three-second pre-roll applies to newly processed violations.

---

### Database Changes

None.

### API Changes

### UI / UX Changes
